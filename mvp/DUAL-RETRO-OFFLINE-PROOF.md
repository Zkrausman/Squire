# Offline dual-retro proof slice (AIDEV-341)

`dual-retro-gate.mjs` is a pure, test-only validator for bounded synthetic fixtures. It is not imported by `run.mjs`, the installed dashboard, or any runtime authority. The requested Squire candidate base is `ce085d3a759aa6ec1d7b6585b2a959a6e2f1cdea`; this module does not inspect Git or establish that the checkout is at that clean head, so the operator must verify it separately. The tests model two declared repositories only: Squire workflow lessons route to the Squire wiki, and target-product lessons route to Gelt's separately scoped project wiki. Every fixture is explicitly labeled `synthetic_fixture`; even a passing result means only `allow` for a **fixture-only simulated decision**. It is not evidence that a merge, review, CI run, run receipt, wiki approval, branch, or repository state exists in reality.

The gate distinguishes each synthetic **merge commit** from its reviewed PR head: the verified merge receipt names its source head and tree; the PR review, hosted CI and Squire run bind to that source head and diff, while the merge tree must match the reviewed head tree. Real GitHub receipts and Git trees must be independently fetched and authenticated later; these are only internally consistent fixture strings. The example routes Squire to `Zkrausman/Squire` `main` and Gelt to `Zkrausman/Gelt` `master`, not to the Linear team/project slug. It checks wiki paths against the narrow `.llm-wiki/wiki/` Markdown allowlist, forbids raw/meta/private paths and source changes, and keeps each repository's simulated PR scope separate. Each one-path PR scope must name the same 64-hex proposed content digest as that repository's change; an independently changed digest stops. Neither digest is computed from Git or authenticated by this offline model. Before returning `allow`, it checks independent review and exact-head hosted CI for each proposed wiki diff and requires a matching, recent base/head ref snapshot for both scopes. A changed, missing, contradictory, or mismatched value returns a named `stop`. Ticket disposition prefers refining a relevant existing candidate; `no_ticket_warranted` requires a reason. These checks validate fixture shape and consistency only—they cannot authenticate receipts, inspect a worktree, fetch refs, or establish reviewer independence.

No fixture values are real receipts. No raw/private material, ticket bodies, or log contents belong in fixture input/output. This slice performs no network access, external fetch, GitHub or Linear action, repository write, credential use, broker invocation, deployment, trading, or actual/autonomous merge. `allow` never runs a command or creates an issue. No live Gelt/ZAR-219 work is included or implied.

The owner-facing orchestration and separately reviewed, wiki-only PRs remain a later pilot stage, only after a **verified Gelt merge** and fresh checks of actual repository permissions, session identity, privacy, safety, diff, review, CI, and refs. The modest onboarding assumptions do not waive any of those gates. The later pilot requires a separate review; this offline proof cannot authorize it.
