# Pause acknowledgment, cancellation, and settlement

This note records source behavior from decision snapshot `50cbf10580670be193d6035763e4c2b9a1a497fa`, reconciled against documentation baseline `8e410c01b58d99ce6934ff80af0cb98993d9c8b0`. It documents existing behavior; runtime behavior is unchanged.

**Decision:** keep pause's existing next-boundary scheduling meaning. A durable pause acknowledgment is not cancellation, an atomic launch shutter, or affirmative descendant settlement. The existing [operations contract](../OPERATIONS.md) and [SQF04 authority contract](sqf04-authority-evidence-contract.md) remain authoritative. This note maps the action boundaries and does not establish a new stop mechanism.

| Boundary | Source behavior | Safe claim |
| --- | --- | --- |
| Durable pause | [Store.pause](../../src/store.mjs#L234) records `paused=true` and an event. The [CLI](../../bin/squire.mjs#L102-L109) and [API pause route](../../src/api.mjs#L62) return that state. The API route does not abort the active controller. | The pause flag was durably acknowledged. That does not confirm cessation of work. |
| Run already sees paused at entry | [run](../../src/controller.mjs#L192-L204) returns before process reconciliation and runtime preflight. | This entry path does not start those later actions. It does not settle older held work. |
| Pause arrives after the entry check | Reconciliation, preflight, and preparation follow the entry check before later loop checks. | Do not claim that a newly persisted flag prevents every startup action already admitted after an earlier check. No timing race was reproduced. |
| Scheduler sees paused | The [main loop](../../src/controller.mjs#L232-L237) waits for currently active promises and returns; it does not abort them solely because `paused=true`. | Scheduling stops at that observed boundary. Already-active work may still complete and project results. |
| Planning or ticket phase starts | The [planning loop](../../src/controller.mjs#L223-L230) and [produceStep](../../src/controller.mjs#L420-L428) check [assertActive](../../src/controller.mjs#L189-L191), which tests the signal and current pause flag. | These checks precede later awaited operations. They are not a lock across every effect or await. |
| Merge phase | The [controller](../../src/controller.mjs#L572-L577) checks active immediately before entering `delivery.merge`. The adapter then performs multiple asynchronous reads and may mutate remote state. | A pause observed before the check blocks entry. A pause after it does not atomically revoke an admitted remote operation; acknowledgment cannot prove that no merge occurred. |
| CLI interrupt or server shutdown | [CLI signals](../../bin/squire.mjs#L119-L129) abort the controller signal. [Control-server close](../../src/api.mjs#L73) aborts active controllers and waits for their promises. This differs from the API pause route. | The signal path requests cancellation; it does not by itself establish settlement. |
| Process cancellation | [runProcess cancellation](../../src/process.mjs#L196-L210) closes the supervisor lifeline; [supervisor stop](../../src/process.mjs#L240-L247) requests target termination. Timeouts and escalation have separate bounds. | A requested stop, closed channel, or direct-child exit is not complete descendant evidence. Existing unknown and fencing behavior remains. |
| Outcome persistence and resume | The [producer wrapper](../../src/controller.mjs#L108-L125) refuses success closure after an aborted signal and otherwise requires a recorded normal outcome. [Resume](../../src/store.mjs#L895-L925) checks other held scopes before retry-state changes. | Terminal operations and pause state cannot release an unresolved producer or authorize duplicate work. Resume is not settlement. |

The [API fixture](../../test/api.test.mjs#L19-L28) exercises durable pause while work is in flight. Its comment about no later merge does not prove that arbitrary pause, check, and remote-mutation interleavings are atomically excluded. This is a fixture-source observation only: no race, pause latency, stopped-process inventory, or actual user outcome was measured. The supported trust model and complete-descendant observation gap are unchanged.

Evidence should distinguish the acknowledged scheduling pause flag, cancellation requested through an actual signal, separately observed process outcome and producer closure, and affirmative settlement. Settlement remains `UNKNOWN` unless the admitted full-worker contract establishes it. This note selects no implementation or stronger acknowledgment protocol. Benchmark and execution conclusions remain unestablished by this source and fixture review.
