# Contract → Implement → Verify

There is one delivery path: **owner-approved immutable Linear snapshot → Implement → fresh independent Verify → exact-head App publication → required CI → owner merge evidence**.

The fetched issue is the contract, not a model-authored plan. The controller persists its bounded snapshot and SHA-256 digest before dispatch. A clean first-pass run launches exactly two independent Pi sessions. A failed Verify can cause one bounded correction cycle only under the controller policy. No model may change the workflow.

## Authority

Implement is the only writer. It inspects, edits, builds, tests and commits one candidate descended from the exact base. The worktree must be clean. Durable architecture, workflow, operational and constraint knowledge belongs only in the target worktree's committed `.llm-wiki`. Evaluate the net base-to-candidate diff; report every changed wiki path or a concrete no-update reason. Never use a personal/host vault or include secrets, transcripts or routine status.

Verify starts with a fresh session and home at that exact candidate. It reviews security, correctness, scope and wiki claims and executes all configured tests. It has read/search/command tools, no edit/write tools. Tracked source is root-owned and nonwritable; root-owned sticky ancestors prevent unlink/rename while allowing build outputs. Git metadata is sealed and the unprivileged process runs with `setpriv --no-new-privs`. Config requires a non-root numeric uid:gid. The runner also deterministically executes configured commands and binds each observed exit to its bounded private output. A nonzero exit is accepted only in a failed Verify report that names the same command and exit; missing, mismatched or passing-report nonzero exits fail closed. The controller independently checks HEAD and cleanliness afterward. Tests requiring source edits are incompatible; fix owner configuration rather than weakening this boundary.

The controller exports and publishes only the verified candidate, validating bundle base, branch, digest and head through the existing GitHub App publisher. It does not merge. Required Node 24 Linux/Windows, native/ACL/filesystem and advanced JavaScript/TypeScript plus Actions CodeQL gates remain authoritative on the published exact head. Model Verify is never CI attestation.

## Failure and evidence

Reports are closed versioned JSON objects: version, outputHead, passed/failed status, bounded summary and phase-specific bounded details. Trusted run/session/profile/input-head identity comes from the controller, not echoed model fields. Reports, process streams and test outputs remain private immutable artifacts. Missing, malformed, contradictory, timed-out or infrastructure-failed output is terminal; preserve the candidate, never promote it.

`correctionPolicy.maxCorrections` accepts only 0 or 1 (default 1); `maxRecordedCostUsd` is a bounded decimal string (default `"10"`). Before another paid phase and before publishing a corrected candidate, Squire requires complete private Pi-recorded cumulative usage under this ceiling; missing cost stops. This is a post-phase safety gate, **not** a provider invoice or a guarantee of a hard mid-call spend cap. A schema-valid failed independent Verify with bounded findings, a closed `code_only` correction recommendation, no explicit owner/host escalation request, and matching host-observed commands may trigger a new unprivileged Implement in the **same fenced workspace**, not an approval. Both old phase sessions, raw reports and host test evidence must be in private custody before the trusted host resets worktree permissions and removes ignored outputs. The new Implement receives bounded feedback, must commit a distinct descendant, and is followed by a fresh independent Verify on the complete original-baseline diff after ignored outputs are isolated. Model-authored recommendations cannot establish security or authority safety; missing, `requires_owner`, `security_ambiguity`, `unknown`, or explicit owner/host escalation requests stop, and a later independent Verify plus exact-head hosted gates are always required. A second failure, missing custody, deadline, head drift or ambiguous execution stops. Failed/terminal states remain immutable, and older states without a correction policy are not correction-eligible. No general resume, supervisor, contract amendment or postterminal remediation is added. The pre-existing typed, zero-effect, pre-result provider launch retry remains distinct and under the original phase deadline.

Run-state schema 2 adds a versioned append-only correction ledger alongside contract, base, latest candidate, Verify disposition, terminal reason, publication, pending external CI and unmerged disposition. Each prior failed candidate/result and private custody reference is retained; the latest exact candidate alone can publish. External CI and merge are not inferred from publication. Historical schema-1 state has a separate read-only status/watch display; it is never normalized into executable state.

## Configuration migration

`modelPolicy` has exactly `implement` and `verify` profiles. Remove old phase profiles, `escalationPolicy`, `reportCorrectionPolicy`, `promptPolicy` and remediation controls; they fail before launch with migration errors. There is no implicit mapping. Use `squire.config.example.json`. Config and launch evidence are captured before detached handoff, with private outside-repository runtime paths and unchanged Windows native ACL boundaries.

Controller-owned phase parent directories and root-owned read-only input files protect the copied contract and prevent the writer from replacing future phase input paths. Phase homes and temporary directories are separate for each attempt; old session bytes are archived in host-private immutable report storage before any subsequent attempt. Private host stdout evidence, not model-writable session logs, is authoritative.
