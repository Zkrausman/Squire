## Data validation

`validateJobSpec(input)` requires approved Table1 fields and optional `fenced_history_ref`, rejects extra fields and returns a frozen copy. UUIDv4 and positive safe-integer budgets are caller-supplied, with no defaults or benchmark caps. Required artifacts are a nonempty unique list of lexical relative paths. Scope and historical reference are text only: no directory resolution, workspace fencing or history reuse occurs.

Inputs are ordinary data records and dense data arrays. Accessors, Proxy objects, custom array iterators and extra array properties are rejected; artifact values are captured once. These defensive rules are not a hostile-JavaScript sandbox.

`validateJobRecord(spec, input, observations)` validates final data with only `SUCCESS`, `FAILED` or `CANCELED` statuses. The required observation record is `{process_group_allocated, process_exit_code, settlement_status}`. Allocation is boolean; exit is a raw observed safe integer or explicit null when unobserved. Settlement is null only for pre-spawn without allocation; allocated groups require one positively asserted `CLEAN`, `ORPHAN_KILLED` or `DIRTY_LEAK` result. Input values must exactly match observations. Missing exit/settlement fields are rejected, with no omission or sentinel coercion. Post-spawn null settlement throws `unrepresentable_settlement`.

Pre-spawn FAILED/CANCELED records accept null exit and settlement. Signals and lost exit observation retain null even after positively observed settlement. Arbitrary integers cannot be recognized as synthetic by their numeric value alone: they are accepted only when exactly bound to the caller's raw integer observation. This pure library cannot authenticate that observation.

Artifacts retain `{byte_count, sha256}` entries under relative paths. SUCCESS requires exit0, all required nonempty artifact assertions and observed CLEAN or ORPHAN_KILLED. DIRTY_LEAK forbids SUCCESS. Structural validation alone cannot prove the prior coordinator history: use lifecycle finalization to enforce cancellation, fences and verification order. No bytes are read or hashed and no custody is established.

Other metadata remains unchanged: requested/reported models and wall/inference timings stay distinct, missing allowlisted usage stays UNKNOWN, supplied totals are not recomputed, and optional error_details accepts only code/signal/classification. Errors name fields rather than supplied values. Trusted metadata strings are not a redaction guarantee.

## Injected lifecycle events

`createLifecycle(spec)` returns a frozen SUBMITTED value. `advanceLifecycle(current, event, payload)` accepts values returned by this module, retaining the same frozen spec. Cloned/serialized or caller-edited states are rejected. Values may be branched by the caller; this is not a durable, globally single-use ledger or an authenticated replay protocol.

Transient states are SUBMITTED, RUNNING, VERIFYING_ARTIFACTS, SETTLING_DESCENDANTS and TERMINAL_SETTLEMENT. Final JobRecord statuses are separate. `terminal_intent` carries the prospective outcome and `record` remains null before finalization.

| Phase | Event and required payload | Result |
| --- | --- | --- |
| SUBMITTED | EVENT_SPEC_VALIDATION_FAILED | Pre-spawn FAILED intent, terminal settlement marker |
| SUBMITTED | EVENT_ADMISSION_PASSED with admission_passed, workspace_fence_passed, history_fence_passed and process_group_allocated all true | RUNNING; these are caller assertions that admission and allocation have occurred |
| RUNNING | EVENT_PROCESS_EXIT_ZERO / EVENT_PROCESS_EXIT_NONZERO with matching raw process_exit_code | Zero proceeds to verification; nonzero enters settlement with FAILED intent |
| RUNNING | EVENT_PROCESS_SIGNAL_TERMINATED / EVENT_PROCESS_EXIT_UNOBSERVED, no payload fields | Settlement with FAILED intent and null exit |
| VERIFYING_ARTIFACTS | EVENT_ARTIFACTS_VERIFIED with complete artifact_witness | Freeze witness, enter settlement with SUCCESS candidate |
| VERIFYING_ARTIFACTS | EVENT_ARTIFACT_VERIFICATION_FAILED | Settlement with FAILED intent |
| Any phase before emission | EVENT_USER_ABORT / EVENT_TIMEOUT_OR_ABORT, no payload fields | Permanently latch CANCELED; settle allocated groups, otherwise use terminal marker |
| SETTLING_DESCENDANTS | EVENT_DESCENDANTS_OBSERVED_CLEAN / EVENT_DESCENDANTS_OBSERVED_ORPHAN_KILLED | Terminal marker; retain prior SUCCESS, FAILED or CANCELED intent |
| SETTLING_DESCENDANTS | EVENT_SETTLEMENT_LIMIT_EXCEEDED_LEAK | Terminal marker, DIRTY_LEAK; FAILED unless cancellation was latched |
| SETTLING_DESCENDANTS | EVENT_SETTLEMENT_OBSERVATION_FAILED | Terminal marker; FAILED or latched CANCELED, null settlement and emission blocked |

A late exit after cancellation can retain its raw integer without restarting verification; a conflicting already observed integer is rejected. A late verified-artifact event while canceled is ignored, preserving an earlier witness if present. There is no transition out of a terminal marker except cancellation before emission; emitted values reject every transition. A specification-validation failure event represents an injected coordinator decision about a structurally accepted spec, not a way to construct an invalid JobSpec.

`finalizeLifecycle(current, input)` requires TERMINAL_SETTLEMENT, a representable settlement observation, exact observed exit/settlement and terminal outcome, and the exact frozen witness if one was accepted. It returns an immutable value containing the validated final `record`. It never produces a record while cleanup is pending or unknown. Cancellation arriving after settlement but before emission still wins. Finalization of an already emitted value is rejected; branching an earlier immutable value is not global deduplication.

## Validation and next-stage dependency

Deterministic injected tests cover pre-spawn absence, signaled/unobserved exits, guarded success, prior failure plus complete cleanup, cancellation in every active phase and during settlement, late zero/artifacts, dirty leaks, immutable emission and withheld unknown settlement. The pure modules perform no filesystem, process, network, provider or clock operations. Finite event handling proves no runtime liveness, actual admission, artifact custody or cleanup.

The next approved stage is SQ-02's metadata-only process wrapper. Its runtime authority, dependencies and stop conditions must be separately satisfied. Mapping unobserved post-spawn cleanup to a final wire value remains a material owner decision: the core safely withholds that record instead. Caller budgets remain explicit; SQ-01 introduces no timeout or kill schedule. Existing host-output, backend, auth, storage, GUI, diagnostic and benchmark gates remain unchanged. SQ-02 has not started.
