# SQ-01 pure core: implemented subset and open decisions

The approved design is Lore's Squire Replacement Plan, canonical plan SHA-256 `af4fcd4614e193932cca9aade5f3a7ad21f7cf859ac0990ee87774a946dc1ba1`, approved HTML SHA-256 `162154bb4695a76784309773d6de90facb1fca44ba2386a406539f2e759b6be9`. The unchanged design keeps its historical PROPOSED label; owner approval is a separate receipt. This repository contains no private snapshot, historical local evidence or design-review transcripts.

The subsequent design clarification, SHA-256 `9e3214504ce34ce1918bd590f0efc13bddb09b12ff6a16750cde674df03cc350`, identifies three unresolved normative choices. This source does not select them:

1. Exit-code null/omission/sentinel representation when there is no process exit observation.
2. The settlement value for a job that never created descendants.
3. Immediate cancellation outcome versus settlement-pending lifecycle representation.

## Implemented APIs

`validateJobSpec(input)` requires the approved Table1 fields and optional `fenced_history_ref`; it rejects extra fields and returns a frozen copy. UUIDv4 is caller-supplied. Budgets must be explicit positive safe integers; there are no implicit defaults or benchmark caps. Required artifacts are a nonempty list of unique, lexical relative paths. The task scope is validated as text only: no directory is read, resolved or fenced by this library. A historical reference is retained as text and grants no artifact reuse.

Inputs are ordinary data records and dense data arrays. Accessors, Proxy objects, custom array iterators and extra array properties are rejected; validated artifact values are captured once. These defensive input rules are not a sandbox for hostile JavaScript or a substitute for the caller's trust boundary.

`validateJobRecord(spec, input)` validates **final data**, with only `SUCCESS`, `FAILED` or `CANCELED` statuses. It supports records with a supplied integer process exit and one of the already specified settlement values. A missing/null/noninteger exit is unsupported pending the design decision; the library never manufactures one. Accepting a supplied terminal record does not decide when cancellation may finalize, or imply that the coordinator witnessed execution or settlement.

The concrete artifact-map entry representation is `{byte_count, sha256}` under each relative path. A successful record requires exit0, assertions for every required nonempty artifact, and a settlement value other than `DIRTY_LEAK`. These are structural consistency checks only. It reads/hashes no files and provides no provenance or custody guarantee. SQ-04 must eventually produce actual witnesses, and the runtime must eventually establish descendant settlement.

Reported model and inference time remain separate from requested model and process wall time. Missing allowlisted usage counters become `UNKNOWN`, never zero; supplied totals are retained without arithmetic reconciliation or summation. Error details accept only `code`, `signal` and `classification` metadata keys. Field validation errors name fields, not supplied values. This is not a content-redaction boundary for strings a trusted caller supplies.

`createLifecycle(spec)` returns an immutable `SUBMITTED` value. `advanceLifecycle(current, next, finalRecord)` implements only `SUBMITTED -> RUNNING -> VERIFYING_ARTIFACTS -> SETTLING_DESCENDANTS -> SUCCESS`. Entering SUCCESS additionally requires a consistent successful final record. Direct success jumps, settlement bypass and transitions out of a terminal state are rejected. The function advances assertions supplied by a trusted caller; it does not execute the named phases or authenticate a serialized history.

Failure/cancellation finalization and the alternate RUNNING-to-settlement path throw `pending_design_decision`. This is an explicit unsupported boundary, not a new failure/cancellation policy or a claim that SQ-01 is complete. A preterminal final record is rejected, and the APIs accept no identity/specification patch during a transition.

## Acceptance and next boundary

Deterministic tests cover required fields, copied immutable identity, path aliases, honest UNKNOWN metrics, final-only status, guarded success, illegal transitions and explicit unsupported cases. The library imports no filesystem, process, provider, clock or network capability. Tests use synthetic metadata and do not read artifact files or launch children. The CI check retains the existing `controller-ubuntu-latest` identity while testing only the replacement pure core.

Complete SQ-01 requires the design-owner selections for the three open cases and review of their exact implementation. SQ-02 is the next existing scoped stage, but it has not started and this partial library does not admit process execution. SQ-03 through SQ-06 and their actual correctness/safety gates remain ahead. No fixture or schema success releases the host-output gate, authentication, security, storage, GUI, diagnostics or real-task execution.
