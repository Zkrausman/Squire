# Three-product baseline v1

Frozen product inputs: the selected pages in Squire Benchmark Briefs at local commit 76fe94dc. One new run per product, fresh seed, no old implementation or model-specific solution in inputs. This is a first baseline, not a statistical claim of improvement. Historical six-case v0.1 measurements and incomplete Status Report trial remain separate.

## Fair run policy

Freeze the delivered pretrial2 Squire source snapshot, Node/browser/CLI/platform identities, Luna xhigh implementation, latest Sol medium planning and fresh review. Squire plans, implements, tests, reviews and locally merges. Each original goal has 48 aggregate agent calls (including plan/review/rebases), at most two implementations and one ordinary repair per ticket, at most four active tickets, three rebases, and 900-second individual job timeout. No goal wall deadline. No special admission, descendant, reserve increase, manual application repair or reset within a scored baseline. Failures stay in the denominator. Routine infrastructure corrections must be explicitly classified and recorded, never relabeled success. Quota waits retain elapsed time.

Run products sequentially to retain a global four-ticket ceiling. Capture all events, structured plans, candidate heads, reviews, local merges, failure/timeout outcomes, intervening operations, known usage and unknown calls. Missing usage is unknown, not zero. Machine/browser/model backend revisions are limited to the identities actually observable; do not claim complete remote reproducibility or filesystem read isolation.

## Independent final acceptance

Controller checks run repository-owned tests and platform compatibility. Controller completion is only backend delivery. Clone the exact delivered main into a separate acceptance checkout; do not change application code. Use documented launch, actual graphical interaction and disposable data. Record screenshot/video or DOM evidence, source/fixture hashes, expected vs observed results and the precise delivered head. Missing/untestable criteria are failed or unknown, never passed. Independent gate runs AFTER local delivery, avoiding review/final-host circular dependencies. Reviewers assess their candidate's component and integration evidence; they may not waive requirements or claim root graphical acceptance.

The orchestrator owns independent final grading and never delegates implementation to the grader. The page acceptance bullets are the complete mandatory criteria. Score each pass/fail/unknown; overall functional acceptance requires all mandatory bullets. Preserve partial credit, controller outcome and functional outcome separately. A partially correct artifact can be inspected diagnostically even when controller delivery fails; diagnostic success does not override that failure.

### Scribble Blackjack Shooter v2

Launch an actual offline desktop window, verify local assets. Read the interpretation recorded before implementation. Play at least three complete loops using the documented controls; exercise rapid/repeated input, an outcome and clean restart. Record what blackjack decisions change in shooting and vice versa; both must meaningfully occur in one loop. Verify in-game explanation, consistent selected rules and visible animated scribble presentation. No reference mechanic is mandated. Assess creative quality separately on 1–5 anchored dimensions: clarity of integration, coherence, visual execution, and enjoyment; retain written evidence rather than claim an objective model-quality score. Functional acceptance never depends on a grader preferring one creative interpretation.

### Local Job Queue v1

Launch the actual graphical client, API and two workers in independently restartable processes using the delivery's documentation. Use independent sales fixtures with quoted category text, empty/negative/fractional fields and exact integer money arithmetic. Assert row counts, quantities and category totals using the oracle output. Submit several simultaneous jobs; same request-ID/exact payload returns same job, conflict rejects. Kill one worker while processing; restart service with pending and finished jobs; observe recovery/history and no duplicate/conflicting final effects. Exercise queued/running cancellation versus completion, explicit retry, malformed/oversize files and graphical disconnect/reconnect. Record real process/control evidence; mocks cannot pass recovery criteria. Source logs and fixture data are disposable, not private user data.

### Local Log Explorer v1

Launch the actual graphical application. Independently generated mixed JSONL/quoted multiline CSV fixtures include equal times with different offsets, duplicate records across sources, missing request IDs, hostile markup, malformed rows, invalid UTF-8 and extra JSON fields. Compare all accepted/rejected counts, stable UTC/tie ordering, AND filters, minute histogram/click range, request correlation and full paginated exports with oracle values. Test saved query CRUD/restart, repeated source replacement, cancellation/interrupted replacement retaining prior snapshot, moved/missing originals, corrupt storage explicit recovery and unchanged source/sentinel hashes. Render hostile content inert. Import the exact 100k/under-50MiB fixture and measure 30s import / five <=2s combined queries on the frozen machine, recording actual responsiveness. Product threshold is the page's performance criterion, not a controller wall deadline.

## Improvement loop

Finish and independently grade all three baselines before framework treatment. Diagnose one bounded hypothesis at a time. Rerun affected benchmark(s) with the same original-goal allowances and input hashes; use the broader suite as regression coverage when the changed behavior spans products. Change models in a separately labeled comparison. Preserve original failures and compare acceptance first, then interventions/calls/known costs/elapsed time and partial criterion scores. Do not optimize to these fixture contents; subsequent confirmation uses fresh fixture variants under the same frozen public contracts.
