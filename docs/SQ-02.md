# SQ-02 metadata-only execution wrapper: source candidate

This slice implements independently ready SQ-02 source against the approved replacement plan, following merged SQ-01. It does not release the specific historical diagnostic holds or implement the proposed UNKNOWN settlement wire amendment. It is a source candidate with deterministic fake validation, not completed native acceptance or a task runner.

## Source surface

`startProcess(spec, invocation, {port, clock, shutdown, signal?})` validates and snapshots explicit invocation data and budgets, then asks the supplied process port to launch once. Invocation is `{executable, args, env, stdio}`: executable and env.TMPDIR must be absolute paths; env is explicitly supplied without merging the host environment; stdio is exactly three caller-owned descriptor numbers or `ignore`. No shell, implicit pipe, captured output, provider call, prompt parsing, command logging or retry is introduced. Workspace/TMPDIR creation, ownership, subscription authority and actual workspace/history admission remain caller responsibilities; a lexical path is not a filesystem fence.

The returned handle contains `exit`, `result`, `settle()` and `abort()`. `exit` resolves on a native leader exit observation. It does not attest descendant settlement. After exit the caller may verify artifacts before calling settle; the task timeout remains armed throughout. Abort or timeout permanently latches `canceled` before initiating settlement. Manual settlement can be superseded by cancellation without resetting shutdown deadlines.

The explicit shutdown fields are positive integer `term_grace_ms`, `kill_grace_ms` and `poll_interval_ms`. No defaults are introduced. The first stop request sets absolute TERM and final shutdown deadlines; repeated abort, settle and exit events do not extend them. A positive matching owned-subtree observation permits SIGTERM, followed by SIGKILL at the original TERM deadline if survivors remain. A subsequent positive complete zero-live observation permits CLEAN without signals or ORPHAN_KILLED after accepted shutdown signalling. Signal dispatch alone never establishes cleanup. Positive live evidence at the exact final deadline permits DIRTY_LEAK. Late/missing inspection, unsupported coverage, conflicting identity or signal denial produces a null settlement and ends control without retry or alternate signalling. Finite scheduling is conditional on bounded trusted synchronous ports and event-loop progress; this code cannot preempt blocking JavaScript, hung synchronous syscalls or a stalled host.

`result` contains only job identity, PID/allocation observation, native integer-or-null exit, signal-or-null, spawn-event-to-exit-callback elapsed milliseconds-or-null, cancellation, settlement, termination reason and fixed failure classifications. It excludes executable, arguments, environment, stream bodies, native exception messages and provider metrics. Missing exit observation leaves both exit and process wall time null; no wall duration is invented at shutdown. Allocation is null after an unobserved spawn request, false only before a launch or a confirmed spawn failure, and true on positive native allocation. This metadata is not a JobRecord and is not automatically serializable as one. In particular, SQ-01 still rejects unobserved spawned settlement, and unknown wall time cannot be coerced into its integer field.

`createNodeProcessPort(ownedGroup, operations?)` is the Linux launcher candidate. By default its launch operation is Node's spawn, with `detached: true`, `shell: false`, cwd from JobSpec, exact supplied env and stdio. Import/factory creation launches nothing. It listens separately for native spawn, exit and error; close is not used as the native exit clock. Errors are projected to fixed classifications without retaining exception messages. Release detaches owned lifecycle listeners and retains a passive error listener so late errors cannot escape or rewrite delivered metadata. It does not unref, kill or hide a surviving child on release.

The required trusted `ownedGroup` control object exposes bounded synchronous `observe(group)` and `signal(group, signal, observation)`. Group identity is `{job_id, pgid, identity}` with an opaque per-launch identity object. Observations must contain exactly those fields plus `live_count`, `coverage_complete` and `signal_safe`. Identity, job and pgid must match, and coverage must positively include the full owned descendant set, not merely leader exit or membership in one numeric group. Signals additionally require signal_safe and explicit successful dispatch from the control implementation. These are trusted port contracts, not security proofs produced by this wrapper. There is deliberately no default observer, signal implementation, kill(0) substitute or numeric-PID-only fallback. Concrete observation, safe signalling, escaped descendants, PID/PGID reuse races, own/helper process handling and their runtime qualification remain unimplemented dependencies for native acceptance. This prevents a generic process-group check from being advertised as complete descendant proof.

`createMonotonicClock()` uses hrtime.bigint elapsed time and chunked timers. Long timer delays are capped to Node's supported single-delay range, after which the wrapper checks the original absolute deadline again. The task ceiling is explicit JobSpec.max_wall_clock_sec; it stays separate from process wall time and provider inference time. max_steps remains the coordinator/provider's separate responsibility.

## Validation and specific acceptance limit

Tests inject the process, clock, group observer and OS launch operations. The Node adapter is tested with an EventEmitter fake instead of a child. Tests exercise native integer and signaled null exits, cancellation during settlement, fixed TERM/KILL timing, task timeout during verification, identity/coverage failures, signal denial without fallback, spawn failure versus unknown allocation, survivor evidence, late observations and private-input exclusion. CI runs these tests with the pure SQ-01 tests; it does not execute the native launcher.

No actual child-tree termination, descriptor drainage or native exit capture has been demonstrated by this slice. The native SQ-02 acceptance action is held pending concrete owned-group controls and a separately bounded authorized runtime validation scope consistent with existing no-rerun holds. The historical nested-child diagnostic must not be replayed as that validation. SQ-05's environmental acceptance and SQ-06 delivery are separate stages. This is a specific native acceptance gap; source development is not blocked and no actual access denial occurred during this source work.

The proposed UNKNOWN wire enum still awaits owner selection. That decision blocks serialization of unobserved post-spawn cleanup and corresponding SQ-05/SQ-06 acceptance; it does not block this SQ-02 source development. No record is emitted or UNKNOWN enum added here. No provider/backend/auth/GUI/benchmark/model run, install, credential or host-configuration change occurs in this slice.

## Primary API references

Node documents that [detached spawn on non-Windows creates a new process group and session](https://nodejs.org/docs/latest-v24.x/api/child_process.html#optionsdetached), while [exit and close are distinct events](https://nodejs.org/docs/latest-v24.x/api/child_process.html#event-exit). Its [monotonic hrtime API](https://nodejs.org/docs/latest-v24.x/api/process.html#processhrtimebigint) provides interval measurements; [timers are approximate and clamp oversized delays](https://nodejs.org/api/timers.html#settimeoutcallback-delay-args). These API properties do not establish this host's runtime behavior or hard isolation. The launcher uses Node's documented detached setsid route to obtain the design's dedicated process group; it does not claim to call a JavaScript setpgid API.
