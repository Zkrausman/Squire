# Source-only startup adoption

The public startup and manager modules are compatibility facades over one internal lexical core. Their factory signatures and exports are preserved. There is no enrollment, grant, arbitrary commit callback or externally supplied release capability. Genuine operation and session records are private WeakMap entries in this loaded module instance; lexical privacy is an ordinary software boundary, not host isolation or authentication.

`factory.adoptStartupOperation(operation, specification, invocation, policy)` accepts a genuine operation only after a complete matching start ACK. Expired time or cancellation never substitutes for ACK. It validates and snapshots the supplied full JobSpec, invocation and policy before preparation. Every spec field, including artifact order and optional history reference presence, must match the privately retained original. The unit must match its captured nonzero InvocationID binding; explicit positive stop grace and matching TMPDIR remain required. All existing host eligibility flags are still caller assertions and must be true; this does not qualify a host.

Preparation uses a private per-operation latch and revision checks around the original clock read. Reentrant state changes, sticky failure or a global reservation conflict cannot mint a target. A prepare failure does not consume adoption authority, but any clock failure or observed cancellation remains recorded. Exact duplicate ACKs remain idempotent. Malformed or conflicting ACKs fence the operation.

The target is assembled privately before commit. It shares the identical mutable monotonic clock cell and original deadline with the source, rather than copying a counter or deriving a fresh budget from the recipient factory clock. The original validated specification and epoch are retained. For an adopted async-stop factory, its injected schedule must share that original source clock domain even though the recipient factory's now reader is intentionally unused. Commit calls no clock, listener or manager callback. It issues neither a second start nor a stop. Cancellation inherited during preparation is mapped to the existing target reason timeout/aborted with its nonsecret source classification retained privately in failure metadata. Caller abort takes precedence when already latched, even if its classification is named deadline. Stop control begins only on subsequent target control/driver calls.

After commit the target is the sole active controller and the startup snapshot reports adopted. A second adoption fails. Source cancellation and sticky failures propagate through private cross-links; late matching ACK cannot clear a fence. A previously observed raw exit remains unchanged by failure propagation. No process allocation or terminal JobRecord is synthesized from adoption. PR156's known-custody coordinator, observation closure and original-deadline behavior remain unchanged.

## Reservations and release

Manager factories and startup operations coordinate in-memory reservations across this module instance. New creates and adoptions check job/unit collisions and overlapping active scopes. Fake tests use unique identities across unrelated fixtures because a new factory is no longer a reservation bypass. This is not cross-process, filesystem or crash-durable enforcement.

A reserved workspace is not a sticky failure. The startup public workspace_quarantined flag remains true after possible dispatch and a valid ACK. Adoption therefore checks acknowledged phase and a separate private failure predicate; it never clears the reservation merely to adopt.

Only the genuine target's canonical complete closed empty observation can authorize coordinated scope release. Raw nullable exact_live_count with populated0 remains valid and normalizes to zero; incomplete closure/coverage, conflicting counts, pending stop ACK or any sticky failure cannot authorize release. Job and unit reservations remain consumed. Repeating release on an old released target must return without mutating reservation sets, including a path now held by a new occupant.

After release, late source abort, clock failure and conflicting ACK append original-epoch private diagnostics only. Existing failure_codes may show those classifications on a fresh frozen snapshot. They cannot change canceled, cancellation_reason, coordinator_returned, settlement_status, admission_quarantined, local_workspace_released or operational control. Earlier returned snapshots stay immutable. No historical event reacquires a scope, undoes release, controls a new occupant, dispatches an RPC or triggers host recovery. The startup workspace_quarantined latch remains a source dispatch/reservation assertion; target local_workspace_released and the private released scope item govern coordinated release. It is not proof that a historical source still holds the path.

## Acceptance and remaining limits

Pure fake-event cases cover the eight reviewed negatives, full spec/capability checks, prepare races, shared clock regression in both directions, deadline/cancellation precedence, coordinated release and coherent adoption into the known-custody coordinator. Existing legacy semantic assertions remain, with fixture identities separated to honor global reservations.

Unsafe/native startup remains disabled. This slice supplies no transport producer, bus access, provider task, native timer, service/configuration change, persistence or host qualification. Process loss destroys these guarantees. Actual MVP execution and conditional benchmarking remain not ready. Provider launch/schema selection, physical custody and environmental/native acceptance are separate dependencies.
