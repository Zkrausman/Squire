# Standalone terminal status reader

Run `node bin/squire-status.mjs PROJECT_CONFIG TICKET_ID [TICKET_ID ...]` to display selected persisted project and ticket statuses. The reader takes only the configured project `id` and absolute `stateDir` from the supplied JSON file, then inspects that project's row through the existing private snapshot reader. It does not validate or execute the rest of the project configuration. Repeated ticket IDs are deduplicated. If no ticket ID is supplied, it prints `no_selected_tickets`; an empty selection does not mean there are no active runs.

Use `--watch=SECONDS` to refresh at a fixed interval from 1 through 3600 seconds. Reads run one at a time, each frame is independently bounded, and Ctrl+C or SIGTERM stops after the current read. The command has no run, pause, retry, process, provider, or controller side effects.

The output separates persisted durable status from OS liveness. Squire's current inspection contracts do not provide verified OS liveness, so every frame says `Liveness: UNKNOWN`, even when a durable status is `running` or `implementing`. The status is a recorded state fact and does not claim that work is currently executing.

Durable freshness requires the stored project's actual `updatedAt` timestamp. A new snapshot does not substitute for a missing update timestamp, and `createdAt` is never used as a fallback. A future timestamp beyond one minute of clock skew is invalid. State older than 24 hours is stale and its project and ticket statuses become `UNKNOWN`. The output keeps the private snapshot's capture timestamp separate from the durable update timestamp, so a fresh capture of stale state remains visibly stale.

The reader verifies the ordinary `project` table and its `id`/`state` columns, selects only the requested project ID, checks the state byte length before returning state text, caps state at the existing 1 MiB limit, and caps ticket rows and selected distinct IDs at 200. Malformed, unsupported, missing, stale, oversized, cross-project, changed, or unavailable data fails closed to `UNKNOWN` with a fixed failure code. The renderer accepts only identifier grammar and enumerated statuses/codes; prompts, ticket bodies, paths, config, errors, logs, and arbitrary stored text are not rendered. Source SQLite bytes and metadata are not changed by this inspection; reads can update filesystem access times as documented by the existing inspection contract.

This is a standalone partial rescope for issue72. It does not integrate with Herdr or its managed terminal pane, and it does not complete the original issue's visual or integration acceptance. Those checks remain deferred until the owner manually unblocks managed-pane access.
