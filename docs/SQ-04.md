# SQ-04 local physical artifact verification

This stage follows the approved replacement plan's SQ-04 dependency on completed SQ-01. It can progress independently of incomplete SQ-02 native controls. It implements a local filesystem verification gate; it does not implement a durable store, remote service, hardlink publication protocol, host hardening or an end-to-end task coordinator.

`verifyArtifacts(spec, {signal?, fs?, expected_capture?})` inspects exactly the declared required_artifacts beneath the task_scope. The default I/O adapter uses ordinary Node filesystem operations. Inputs retain the SQ-01 immutable JobSpec contract. Scope must be an absolute canonical directory rather than a filesystem root or symlink alias. Each relative path is already validated by JobSpec; the verifier rejects symlink components, directories and special files, missing files and zero bytes.

For each regular file it opens a read-only descriptor with O_NOFOLLOW and O_NONBLOCK, checks descriptor identity against path metadata, hashes actual bytes with SHA-256 in bounded buffers, checks EOF against the initial size, and compares descriptor/path metadata and containing-directory identities afterward. It reads no undeclared file body. A growth/shrink, visible metadata/identity change, failed read or failed close rejects the capture; all witnesses are discarded rather than returning partial accepted evidence. An abort is checked before I/O and between asynchronous operations; an opened descriptor is closed in finally. It does not preempt a hung filesystem syscall or promise.

A successful result is `{job_id, verified: true, artifact_witness, failure: null}` with the existing `{byte_count, sha256}` entry representation. The returned map and entries are frozen. Failure returns verified false, an empty witness and fixed `{classification, artifact_path}` metadata; native error messages, absolute host paths and file content are excluded. Invalid API configuration throws ContractError before inspection. The module performs no writes, directory creation, process launch, network operation, provider call or JobRecord emission. Caller integration must map a false result to EVENT_ARTIFACT_VERIFICATION_FAILED; exit0 is not an override.

Optional expected_capture is `{job_id, artifact_witness}` for the same job and exact required paths. It is structurally validated and copied before I/O, then compared with actual byte counts/digests. A changed file rejects with expected_mismatch. This is an explicit supplied comparison reference, not a cache, historical import or proof of who authored the bytes. No prior run directory is read or reused.

## Caller responsibilities and limits

The caller must supply an admitted workspace it owns and a quiescent file tree. This verifier does not create the workspace or prove fresh job output, history fences or subscription authority. It cannot prevent a hostile writer or directory race from changing bytes/paths between checks; metadata equality is not a coherent-snapshot proof against an adversarial host. O_NOFOLLOW protects the final opened component, not an atomic traversal of every parent directory. Ordinary owned staging and hashes provide inspection and integrity witnesses, not hardened path confinement or trusted custody. No openat2, pidfd, special hardlink, filesystem durability/locking or no-clobber qualification is attempted.

The successful capture is local evidence about bytes read during this call. Files can change afterward; later promotion/review must bind and reverify the intended capture rather than infer continuing immutability. File-reading itself may affect normal access-time metadata; source file bytes and permissions are not modified by the verifier. Directory/path observations are not retained in public telemetry. Fixed buffer size is an implementation memory bound, not a new artifact-size budget or product timeout default.

## Validation and stage status

Deterministic tests create uniquely named synthetic temporary directories beneath test/, use ordinary regular-file operations and remove only those fixtures in finally. They test known SHA-256 bytes, nested paths, missing/empty outputs despite synthetic exit0, leaf/parent symlinks, same-job expected captures and modified bytes, visible concurrent changes, identity changes, abort and resource closure. Read denials and close failures use injected errors instead of changing permissions or probing restricted paths. No child or model executes; no mount, lock, durability or historical diagnostic is tested.

These physical file fixtures validate the local verifier implementation, not storage-backend admission, hostile-host custody or SQ-05/SQ-06 delivery. Native SQ-02 acceptance remains incomplete. The owner-approved UNKNOWN amendment is implemented separately in the pure core; it grants no cleanup assurance, automatic retry or historical rewrite. SQ-03 adapters and SQ-06 integration are outside this slice; all diagnostic, authentication, backend, GUI and benchmark holds remain unchanged.

[Node's file-handle API](https://nodejs.org/docs/latest-v24.x/api/fs.html#class-filehandle) supplies descriptor reads/stat/close, and [SHA-256 hashing](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptocreatehashalgorithm-options) consumes the bytes read. These API references do not qualify this host's storage durability or path-race behavior.
