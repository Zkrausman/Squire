# Limited foreground MVP

This additive path implements the owner-approved smaller scope. The older manager, lifecycle and full-settlement APIs remain intact. `runLimitedAgyTask(specification, runtimeOptions)` executes one fixed-profile AGY foreground public-text task using ordinary Node child-process APIs, without a shell, detached process group, bus client or native addon. Only Flash3.8High/high, the pinned executable and fixed flags are accepted. It makes no descendant-containment, crash-recovery, durable-admission, max_steps or workspace-reuse promise. Standard provider authentication may read the CLI's existing user state; Squire does not inspect credential contents.

The separate `LimitedJobRecord` reports observed direct-child exit, nullable raw code/signal/wall time, bounded I/O, unknown metadata and persistence independently. `LIMITED_SUCCESS` means exit0, complete bounded provider output, valid four-field task payload and successful exclusive publication. It is not the older SUCCESS/CLEAN claim or a content correctness assessment. `task_outcome_evaluated` stays false; semantic review is separate. Missing counters remain UNKNOWN and observed zero remains zero.

Prompt/stdout/stderr limits are 32768/1048576/65536 bytes. Stderr content is discarded; stdout uses one capped arena. Complete exported profile decoding supplies UTF8, duplicate-key and surrogate checks; an additive payload validator enforces summary, enforced_limits, known_limitations and containment_guarantee. Manager identities are never fabricated.

The deadline is derived once from a monotonic clock. Timeout and user abort latch intent; TERM then KILL are attempts against the direct ChildProcess handle only. An observed exit cancels later signals. This is neither atomic PID-reuse protection nor descendant cleanup. Caller return and all timers depend on a responsive parent event loop. After the finite signal windows, an unsettled child is unreferenced from active control, streams are destroyed and passive error/late-exit observation remains. Late evidence cannot rewrite the returned frozen record. No automatic retry or workspace release follows.

Exit and pipe drain are separate. A child can exit while other processes retain inherited FDs. The drain timer returns incomplete I/O rather than waiting forever; destroyed/closed-without-end streams cannot become successful drain. Persistence also has a finite response budget. Complete bytes are written to an exclusive stage in a previously absent dedicated run directory and atomically linked without replacement to the output name. This does not claim crash durability or external-writer exclusion. On uncertain persistence, files may remain; nothing is removed or retried automatically. A published file does not override timeout/cancellation.

The native entries are `runLimitedAgyTask`, and a separate `runInertTimeoutAcceptanceProbe` fixed to `/bin/sleep ['30']` with a one-second budget. Neither accepts arbitrary executable/argv. The internal core requires explicit ports for synthetic tests and supplies no native defaults. The existing process-group wrapper and manager collector are bypassed, not weakened.

The explicit `acceptance/limited-mvp.mjs positive` entrypoint carries the exact reviewed public prompt and fresh run-ID output path. It is never part of CI. The operator first verifies CLI1.4.3, the selected allowed catalog entry, signed-in subscription, effective CreditsOff and available quota. After one positive run and separate payload review, the operator may execute `acceptance/limited-mvp.mjs timeout` exactly once. Any failure stops acceptance; no old harness/qualification replay, fallback, security changes or benchmark is authorized here. Until actual gate receipts exist, implementation and synthetic tests establish source behavior only.
