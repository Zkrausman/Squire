# Current-run telemetry

The controller captures invocation identity, profile, timestamps, duration and bounded private Pi JSON stream evidence for Implement and Verify only. A zero-effect provider launch replacement retains a separate generation. A clean run has two sessions. For the owner's per-run Pi version, authoritative accounting requires explicit `willRetry: false`, a final `agent_settled`, nonzero usage on every successful assistant response, and a supported event stream. Missing/unsupported events (including compaction usage not reconciled by this parser) yield incomplete/unknown accounting, never authoritative zero. The terminal authority label is version-neutral for new runs; legacy 0.84.4 artifacts remain readable unchanged. This change does not backfill historical telemetry or claim complete compaction accounting.

It proves serializer shape, not that every paid 0.87 run yields complete accounting. Unexpected shapes still become incomplete/unknown; do not promote the fixture into a claim of observed paid usage.

Terminal accounting separately records candidate identity, Verify disposition, terminal reason, publication state, pending external exact-head CI and unmerged disposition. Unknown usage/duration stays unknown, never an invented zero. Telemetry capture failure cannot authorize replay or imply a passing workflow.

`squire telemetry RUN-ID --json` reads the private terminal artifact. Terminal summaries are immutable and cannot promote a candidate. Public PR evidence excludes raw prompts, ticket descriptions and private process logs. Hosted CI and owner merge evidence remain external exact-head authorities.
