# Pure StopUnit message codec

This source-only module describes messages and validates supplied reply/signal data. It opens no bus, sends no command, subscribes to no signal and creates no service. The existing async StopUnit branch can consume its synthetic successful response after known custody.

`encodeStopUnitRequest` requires a captured job/unit/InvocationID binding, a caller-supplied pinned manager unique owner and explicit `fail` job mode. It supports the narrow `:digits.digits` owner profile and canonical uint32 job paths, rejecting other representations. It returns immutable metadata addressed to that owner. Resolving and authenticating the owner is a future qualified transport obligation.

`captureStopJobReply` checks the expected owner, request serial and single object-path reply. Its queued-job receipt is not a transaction acknowledgement. `decodeStopJobRemoved` requires matching manager headers, job ID/path and unit. Only `done` produces a transaction acknowledgement; other matched results remain UNKNOWN, and unrelated events remain UNRELATED. Invalid structured data throws without exposing supplied result text. Plain data tuples are required; getters and proxies are rejected.

The [systemd manager API](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.systemd1.html) documents StopUnit with name/mode inputs and a job-path result, and JobRemoved with job ID/path, unit and result. InvocationID is absent from that signal. The codec carries the expected InvocationID under the existing exclusive epoch authority requirement; it does not independently attest it or supply atomic compare-and-swap. The future transport must establish authentic message provenance, subscribe before dispatch, correlate serials, handle early signals and disconnects, and bound and cancel its own resources. None is supplied here. Receipts are caller-owned data, not unforgeable custody evidence.

Job completion never establishes descendant emptiness, a live count, settlement or reuse. Fresh complete closed cgroup evidence remains necessary under the custody contract. No async StartTransientUnit policy is added: start submitted without custody/InvocationID acknowledgement at deadline remains deferred pending the owner decision. No runtime, authentication, host-service, security or benchmark qualification follows from these pure tests.
