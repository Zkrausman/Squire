# Conditional systemd user-manager custody — source contract

SQ-AMEND-2026-10-CUSTODY-03 is owner-approved for source interfaces and synthetic tests only. It conditionally replaces the task-local guardian model with longer-lived Linux systemd user-manager custody. This repository contains no bus adapter, service installation, lingering change, native acceptance or host qualification. Importing the module or constructing the factory performs no native I/O. Execution remains disabled until the required host guarantees are established and a specific native operation is authorized.

## Injected service branch

`createManagerCustodyFactory({manager, clock, qualification})` requires explicit synchronous, bounded injected ports. The manager exposes only `startTransientUnit(request)` and `stopUnit({binding})`; the clock exposes `now()`. There is no default transport, KillUnit, PID enumeration, pidfd, process-group fallback, polling timer or recovery loop. Actual transport serialization, asynchronous acknowledgement handling and scheduling remain future work. The shared `captureInvocation` validator snapshots the invocation without reading host environment or executing it.

All host qualification assertions must explicitly be true before a session can be created: stable manager lifetime; retention of failed/non-empty units after coordinator disconnect; exclusive epoch lifecycle authority; launch inside the unit cgroup before exec; and cgroup-v2 descendant coverage. These injected assertions are trusted preconditions, not host tests or a production admission mechanism. RefUnit alone does not satisfy lifetime or retention across client disconnect. Surviving processes can consume resources after the coordinator returns; the external manager retains responsibility only under these qualified guarantees.

`factory.create(spec, invocation, {unit_name, stop_grace_ms})` reserves a fresh unit name, job identity and canonical absolute workspace. Names and job identities are never reused by this factory. Its local reservations do not establish global non-reuse after restart, crash or another client; external exclusive lifecycle authority is mandatory. An explicit positive stop grace is required; no numeric default is introduced.

`session.start()` issues one service request with mode `fail`, Type=exec, ExitType=cgroup, KillMode=control-group, Restart=no, KillSignal=SIGTERM, SendSIGKILL=true, FinalKillSignal=SIGKILL and TimeoutStopSec from the explicit millisecond grace. These are source-level property names, not a claimed D-Bus wire schema. The worker must be executed directly in the unit cgroup before execve; starting it elsewhere and migrating it later violates the contract. The response must acknowledge that launch property and manager custody, binding the requested job/unit to a nonzero InvocationID. Unit name plus InvocationID identifies an exclusive epoch; it is not atomic compare-and-swap or group-dispatch proof.

The new manager observation interface explicitly defines `live_count` as integer or null. It is separate from the older numeric process-group adapter; there is no automatic conversion, wiring or implicit revision of that older public interface. The systemd custody branch must not be passed to `createNodeProcessPort` or the old signal-based wrapper.

## Observations and cancellation

`observe({binding, populated, launch_closed, coverage_complete, exact_live_count})` accepts only a matching epoch. `populated` is the injected cgroup.events observation (0, 1 or null); neither SubState=dead nor JobRemoved is an input proof. Only populated=0 with closed launch and full coverage establishes empty, count=0 and CLEAN, or ORPHAN_KILLED after a StopUnit request. Populated=1 does not supply an exact count: the count remains null unless separately observed. Unsupported coverage, indeterminate/zombie state or missing evidence leaves an unknown count and UNKNOWN settlement. A positive covered populated=1 observation after the task deadline establishes DIRTY_LEAK; an earlier positive sample is not reused as post-timeout evidence.

`settle()` requests StopUnit at most once. Its manager-job acknowledgement records transaction acceptance only. The qualified manager must implement the reviewed stop policy: control-group SIGTERM plus SIGCONT, the explicit stop timeout and SIGKILL escalation. The source controller does not send signals, implement escalation or infer empty from stop acknowledgement.

`abort()` permanently latches cancellation. `tick()` uses the explicit monotonic task deadline; repeated operations do not extend it. Native integer exit observations are retained unchanged by `nativeExit({binding, code})`; null remains null. Native exit, successful stop dispatch or cleanup cannot remove cancellation or establish task success. There is no JobRecord emission, artifact integration or model/provider call here.

This is a caller-driven state contract, not an autonomous runner. After acknowledged custody, abort/deadline requests a bounded coordinator return while the qualified manager retains responsibility. Trusted ports and callers must be bounded and drive tick on time; JavaScript cannot preempt a blocking port or guarantee event-loop progress. `coordinator_returned` is a source decision marker, not an observed process exit. The session can receive later cleanup observations as immutable successive snapshots; earlier snapshots are never rewritten.

## Failure and workspace fences

Start/stop uncertainty, conflicting identity, malformed observations, clock regression or manager disconnect permanently latch UNKNOWN and quarantine for this session. No retry, alternate unit, fallback signal or automatic recovery follows. A disconnect revokes the custody acknowledgement; the source cannot prove continued custody, host survival, crash-safe admission quarantine or durable telemetry. UNKNOWN is reporting, not cleanup. No final schema is widened beyond the separately approved UNKNOWN amendment.

The workspace remains blocked until matching closed/full-tree empty evidence exists. `releaseWorkspace()` releases only the local reservation after that proof and freezes further operational use of that session; unit/job reservations remain consumed. Release is explicit, not triggered by leader exit, timeout, stop acknowledgement or UNKNOWN. Once UNKNOWN is latched, this session cannot clear quarantine. External review/reconciliation after a failure is not implemented. The in-memory factory is not a durable host admission ledger, and it must not be used as one.
