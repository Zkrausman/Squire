# Local rejected-response diagnostics

The selected Q218 coding task can retain a rejected, well-formed response locally. This is a diagnostic path, separate from accepted source publication. The source format rules remain unchanged: 100–65,536 UTF-8 bytes, with the existing encoding and markdown checks. A retained rejection never gets an accepted source witness, never enters syntax/program execution, and never makes generation or the task successful.

For the eligible too-small, markdown and too-large rejections, the collector measures the full decoded response UTF-8 length, including an empty response. The measurement is distinct from envelope bytes and token counters. At most 65,536 raw prefix bytes are copied for retention. A prefix can end inside a multibyte UTF-8 sequence. Invalid envelopes, missing strings, encoding rejections and primary process/IO/deadline/abort failures have no eligible capture; their unavailable length remains null. Validation order is preserved.

The filesystem adapter uses five fixed slots under the owner's local state directory, outside source repositories and task workspaces. Each slot has at most one raw inode, at most 65,536 bytes; staging and publication hard links alias that same inode. Exclusive claims, closed metadata files of at most 1,024 bytes each, and a bounded listing of the five owned slot directories keep the namespace finite. The raw storage ceiling is 327,680 bytes. Ancestors must already exist, be non-symlink directories owned by root or the current UID, and have no group/other write bits. The managed root and slots require owner-only directory permissions; new payloads and metadata use owner-only file permissions. Existing ancestor permissions are never changed.

Publication uses exclusive stage creation, complete write/close, nonprinting local hash/readback verification, no-clobber hard-link publication, then removal of the owned stage alias. The adapter never deletes an unowned stage or compensates by deleting a final payload. Detected interruption or uncertainty fences the adapter and leaves the slot reserved. An uncertainty marker or interrupted cleanup tombstone blocks reuse. Active or UNKNOWN claims cannot be reclaimed just because 24 hours pass. Only positively settled, owned, expired entries qualify for bounded cleanup. Disk state alone is insufficient: the same adapter must retain a positive settlement observation that has not been revoked by abort. A later process or adapter refuses automatic reclamation of persisted entries, even those marked SETTLED; no durable caller-ACK recovery is invented. Capacity can therefore stop later operations despite logical expiry. No unrelated directory or quarantined task is scanned or deleted.

The 24-hour policy is logical expiry, not OS denial or physical deletion while the host is idle. There is no public raw reader. A local human must respect expiry when inspecting a capture offline; no verified offline viewer is supplied here. File permissions do not isolate data from the same UID or root. Ancestor checks do not remove hostile-writer TOCTOU races. No crash-proof ledger, durable recovery, forensic erasure or hostile containment is claimed.

The AI custodian must not read a real captured body through tools, model prompts, terminal output or transcripts. Raw content, capture paths, slot IDs and content digests must never enter Git, PRs, CI artifacts, Library, wiki or telemetry. A local adapter may perform nonprinting write/hash/readback internally. Tests use hand-authored public synthetic bytes only. If the safe metadata cannot answer a necessary semantic question, stop with the local-human-inspection capability gap rather than ingesting raw bytes or guessing.

The only exported retention sidecar fields are fixed status/stage/reason/error enums, exact response byte count, retained byte count and a truncation boolean. The closed LimitedJobRecord schema and existing metadata normalization remain unchanged. Dedicated retention cancellation uses the original task deadline; it cannot reset or extend the task budget. Already-aborted/reentrant signals prevent a new retention call. A pending I/O owner retains its copy until observed settlement even if the bounded caller returns UNKNOWN; late observations never rewrite a returned record. Timing assumes a responsive parent event loop and does not prove filesystem cancellation.

Preparation and the admitted entrypoint check private capture availability before generation. Imports/default entrypoint invocation do not create private storage or dispatch work.
