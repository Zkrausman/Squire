# Squire MVP Architecture

## Summary

The accepted AIDEV-214 design makes [Squire](/entities/squire.md) a trusted TypeScript controller around one isolated ticket workspace. It separates deterministic controller mechanics from product decisions made by an independent Orchestrator and phase sessions.

The design fixes five independent top-level Pi sessions, immutable result envelopes, current-head Review/Test gates, finite recovery, and a controller-mediated delivery boundary. It also separates AIDEV-216's control-plane seams from AIDEV-224's concrete ledger and intake work.

## Key Takeaways

- Workflow truth belongs to trusted state, Git observations, and validated artifacts—not terminal text.
- [Five-session Pi RPC topology](/concepts/five-session-pi-rpc-topology.md) is a fixed lifecycle boundary.
- [AIDEV-216/AIDEV-224 ownership](/syntheses/aidev-216-and-aidev-224-ownership-boundary.md) prevents duplicate persistence implementation.
