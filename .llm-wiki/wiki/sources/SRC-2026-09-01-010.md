# AIDEV-216 Review Attempt 4 Findings

## Summary

Independent Review attempt 4 confirmed that pre-settlement allocation stalls were fenced, then identified a second race at the opposite side of an asynchronous operation. When a side effect settled and the mandatory post-step lease renewal failed, the caller had not yet received the result needed for cleanup. A completed spawn therefore leaked an untracked live process, while a completed generation claim left the exact registered session permanently in `launching`.

R4-001 requires settlement-aware compensation. Process creation must be exposed at creation time rather than only through later promise return; every returned process must be observed terminated after ownership loss. Resumed generations need the same persisted allocation owner/token and state machine as first sessions. Exact-token recovery must clear or terminalize provisional ownership and mark a committed resumed generation failed, while an uncertain first-session spawn remains fail-closed for infrastructure reconciliation.

## Key Takeaways

- Pre-operation fencing does not expose a side effect that commits immediately before post-operation renewal fails.
- Spawn factories need a synchronous creation callback so cleanup cannot lose a process behind promise scheduling.
- Compensating persistence must be exact-owner/token, idempotent, finite, and require observed process exit before changing spawned state.
