# Background run state and status

A background Squire run is a detached one-shot controller, not a daemon. The invoking process first creates a durable per-ticket reservation and version-1 JSON state, binds any production source-commit evidence as a second serialized pre-handoff update, then launches the installed CLI with ignored stdin, append-only file-backed stdout/stderr, `detached: true`, `windowsHide: true`, and `shell: false`. It returns the run ID after the operating system confirms spawn. The detached child is the sole lifecycle writer after that handoff.

The launch binds the child to the SHA-256 of the exact selected config bytes and the absolute selected config pathname, as well as to persisted repository slug, absolute repository path, source ref, base branch, log paths, and (for the production Docker adapter) the source commit SHA. Relative paths in a configuration therefore cannot silently resolve against a different copy of the same bytes during child bootstrap. The configuration parser rejects unknown fields and legacy root aliases, so `modelPolicy` and `dataDirectory` are the canonical JSON configuration names; `SQUIRE_DATA_DIR` is the only data-root environment override and takes precedence over the JSON value, while `paths.state`, `paths.bridges`, and `paths.staging` remain narrow compatibility paths. New launches also persist combined `launchEvidence` and a controller-owned captured-material file bound to the reserved run, ticket, repository/source identity, config pathname/digest, and state directory. The child rejects missing, corrupt, or wrong-binding material before claiming; direct `runReserved` has the same requirement. It consumes captured raw bytes and once-normalized configuration, never rereading original config/prompts or reparsing its environment. The exact state-store directory arrives through private bootstrap transport rather than rediscovering a data root. Thus material, identity, state-path, and other bootstrap failures can still record terminal evidence against the unclaimed reservation. Original source files may disappear after capture without changing the launch. Legacy states remain readable but cannot authorize material-free detached execution. See [immutable layered prompt policy](/concepts/immutable-layered-prompt-policy.md) for digest and source-trust boundaries. Before detached handoff the Docker adapter resolves the configured source ref and persists that commit; child preparation verifies the ref still names it before creating bridge or staging resources, then pins the verified commit into a temporary clone-visible ref and compare-deletes only its own temporary ref. A moved mutable ref therefore fails closed instead of silently changing the sandbox base. Configured source revisions reject whitespace, control characters, and option-like leading dashes; Docker passes them as one `execFile` argument after Git's end-of-options marker.

## Detached fixture cleanup boundary

Production spawn handoff is not process-exit evidence. The two real detached-log tests in `test/personal-background-status.test.ts` use a test-only authenticated loopback barrier: the child flushes both inherited logs before readiness and remains responsive until release. The direct fixture retains the real spawned `ChildProcess` and awaits its actual `close`; the short-lived launcher fixture first proves launcher close while the child still answers a fresh challenge. It then acquires a retained native process reference (`OpenProcess(SYNCHRONIZE)` on Windows, `pidfd_open` on Linux), and challenges the same authenticated child again **after acquisition** to exclude PID reuse. Only OS-signaled exit plus successful observer close proves indirect child exit. Socket closure, launcher exit, descriptor-close acknowledgements, and marker files are not exit proof.

`test/helpers/detached-process-fixture.ts` owns coordination, processes, and deadlines. Failure teardown closes coordination for graceful child shutdown and reaps owned processes; an unbound observer is cancelled through stdin. Deadlines bound failures, not liveness checks. Without intended-child exit proof, retain the fixture root with its path in the error. With proof, attempt each log unlink once and remove the root once; a failed unlink retains the root rather than retrying via recursive removal. Production lifecycle, retry budgets, PID termination, ACLs, and elevation are unchanged.

The test-only native observer is built via existing node-gyp infrastructure on Linux and Windows; Windows production targets remain Windows-only. Linux validation requires the normal supplied C++ compiler and a pidfd-capable kernel, with no polling fallback or temporary compiler shim. Native Windows Node 20.17.0, 22.9.0, and 24 remain external pre-merge causal gates: both named detached tests must execute and pass, not merely skip or appear in a green job; the bounded native recovery probe remains separate required evidence. Observed busy logs may persist after child descriptor-close acknowledgements and clear only after actual exit; underlying lock internals are not established. This fixture correction does not resolve historical PR30 terminal EPERM/cancellation, close pith#162, or authorize merge.

## Persistence and status

Windows existing-state replacement uses native FileRenameInfoEx POSIX semantics on local fixed NTFS, with pinned ancestors and regular, single-link source/destination checks. A delete-sharing reader may retain old bytes while new opens see the complete replacement. Readers denying delete sharing and genuine access denial still fail closed; unsupported API/filesystem combinations have no legacy fallback. State CAS, immutable identity, original/secondary error reporting, reservation release and bounded retries are unchanged. Initial exclusive creation and best-effort outbox replacement are outside this change. The controlled open-reader mechanism is distinct from the still-unattributed historical EPERM/cancellation incidents. See [Windows state replacement](../../../docs/windows-state-replacement.md) for scope, limits and regression contracts.

JSON updates use a per-run directory lock around the version check and atomic replacement. Each update boundary carries a private owner marker, so cleanup is ownership-checked as well as serialized: only one proposed version `N+1` can follow version `N`; a stale writer fails instead of replacing newer workflow state. A lock left by a crashed writer is intentionally ambiguous and fails closed. Every `.json` state filename must be a valid run ID and must match the record's `runId`. The reserved-to-started claim and unclaimed bootstrap-failure transition combine that per-run CAS with the existing short-lived per-ticket operation boundary, so ownership and state transition are one operation. Reserve and release also pass through the ticket boundary, so an old release cannot overlap a replacement reservation. Ticket reservation locks are not opportunistically reclaimed; empty or malformed ownership records are ambiguous. Only the exact owner may release after its readable terminal state exists, preventing an old releaser from deleting a new owner's lock.

Before child handoff, SIGINT or SIGTERM aborts startup, persists `interrupted` evidence, and releases the reservation. The parent re-resolves configured state and log destinations immediately before reservation and rejects destinations then resolving inside the repository. On POSIX, log opening also refuses a final-component symlink; these checks do not claim race-free ancestor or hardlink protection. After handoff, the child must own the exact reservation before claiming the persisted reserved state, and bootstrap fallback terminalization requires the same ownership. A forced kill or power loss can still leave an ambiguous reservation; this no-daemon design does not infer liveness or automatically reclaim it.

`status` reads only persisted state and reservation ownership. A ticket selector requires its reservation to match exactly one readable active state; an orphan or mismatched reservation is reported as ambiguous even if an older terminal state exists. An exact run-ID selector returns that exact persisted record when a different owner is a readable active replacement for the same ticket, while a running record that has lost ownership and every unreadable or inactive owner remain ambiguous. Human-readable output escapes CR, LF, C0, C1, and ESC from external strings, including ticket titles, errors, profile values, URLs, and log paths.

Every Implement attempt now carries a closed project-wiki disposition. `updated` names the complete set of canonical `.llm-wiki/...` paths changed in the cumulative committed diff from the run base SHA to that Implement HEAD and gives a concise durable-knowledge summary; `not_required` gives a concrete reason. The host controller derives the same path set with a bounded NUL-delimited Git diff inside `/ticket/workspace` and fails closed on missing, malformed, unsafe, duplicate, or contradictory evidence before Review starts. This evidence is persisted with the Implement result, so exact-head Review, Test, Retro, bundle, and PR gates cover required wiki commits.

Implement evaluates durable architecture, workflow, operational, and constraint knowledge only in the target worktree. Personal/host vaults are never imported; routine status, transcripts, secrets, and unrelated notes do not belong in the committed project wiki. Any pre-existing uncommitted control-worktree wiki backlog is a separate reviewed reconciliation, never feature-PR input. Review is independently instructed to reject those cases and any disposition/content inconsistency. The PR publisher validates the disposition and renders exactly one canonical `## Knowledge` section with the update summary and paths or the no-update reason; legacy bodies may gain that section, but duplicate, malformed, or ambiguously placed Knowledge sections fail closed. Review, Test, and especially Retro do not mutate the wiki; Retro remains read-only after Test and only publishes lessons/follow-ups. A selected Retro lesson can become a wiki change only in a later gated run, with fresh Implement, Review, Test, and Retro evidence.
